# 개발자 1인 개발 시작 — v0.9

Career Evidence의 전체 개발은 개발자가 맡는다. Claude Code가 필요한 웹·API·DB·작업 실행기 코드를 같은 사용자 흐름 안에서 구현하도록 도와줘. 협업자의 개발이나 필수 검토를 기다리지 말아줘. 협업자의 검수·데모 도움은 선택이며 아직 배정된 일이 아니야.

패키지·운영 기준은 v0.9, 제품·API 계약과 기초 코드 기준은 v0.7이야. 문서를 준비한 것과 제품 기능을 구현한 것을 구분해줘.

## 먼저 확인

1. CLAUDE.md, DECISIONS.md의 현재 결정, docs/state/PROGRESS.md, docs/state/HANDOFF.md, docs/CODEMAP.md, docs/SOLO_DEVELOPMENT.md를 읽어줘.
2. 실제 작업 경로·Git 상태·사용자 변경·실행 명령을 확인해줘. 이 패키지는 사용자 컴퓨터의 최신 개발 결과를 알지 못하므로 기존 구현·DB·설정을 보존하고 필요한 지침만 병합해줘. 새 ZIP의 코드로 통째로 덮어쓰지 말아줘.
3. docs/solo/tasks.json의 S01과 `prompts/01-resume-search.md` 중 원본 입력·경력 확정 범위, 관련 제품 명세·UI·v0.7 계약을 좁혀 읽어줘. 과거 팀 협의안의 담당자 확정이나 두 번째 사람의 검토를 개발 전제로 적용하지 말아줘.
4. 기존 코드에서 재사용할 부분과 미구현 경계를 간단히 확인한 뒤 바로 구현해줘. 새로운 전체 기획만 작성하고 끝내지 말아줘. 필요한 환경 점검과 관련 기존 검증만 실행해줘.

## 이번 구현 단위: S01

**소유권·저장 기반 → 실제 텍스트 PDF/텍스트 입력 → 원문 추출·후보 확인 → 사용자 수정·확정 → 확정 경력 재열람**을 UI·API·DB까지 연결해줘.

- 현재 DB와 v0.4 계약을 보존하고 v0.7 추가 migration을 명시적으로 연결해줘. 기존 객체 검증·metadata도 버전을 인식하게 하며 DB 삭제나 reset으로 해결하지 말아줘.
- 서버가 확인한 principal/workspace 소유 범위로 문서와 경력을 조회해줘. 로컬 개발 세션과 운영 사용자 인증을 구분하고 클라이언트의 owner ID만 믿지 말아줘.
- 텍스트 PDF의 실제 bytes를 받는 업로드와 텍스트 붙여넣기를 구현해줘. 원본 hash·형식·크기·추출 상태·원문 위치를 보관해줘. PDF 추출에는 키 없이 실행 가능한 로컬 도구부터 검토하고 필요한 의존성만 추가해줘.
- 추출 후보와 원문을 함께 보여주고 사용자가 수정·확인한 뒤 경력 revision을 만들어줘. 희망 조건은 사실과 구분해줘. 확신할 수 없는 추출은 미확인으로 표시하고 경력이나 성과를 지어내지 말아줘.
- 추출 중·빈 추출·미지원 형식·추출 실패·확인 전 상태·권한 오류를 실제 응답과 화면에 연결해줘. 스캔 PDF와 아직 지원하지 않는 DOCX는 가능한 복구 경로를 안내해줘.
- `fixtures/resumes/`의 합성 파일 두 개를 실제 입력 경로에 통과시켜 확인해줘. 코드에서 프로필을 선택하거나 고정 preview를 보여주는 것으로 입력·추출 구현을 대체하지 말아줘.
- 새로고침·재시작 뒤 원본과 확정 경력을 다시 읽을 수 있는지, 확인 전에는 확정 경력으로 취급하지 않는지, 다른 사용자의 자료 접근이 거절되는지 검증해줘. 수정한 코드에 필요한 테스트·typecheck·build와 실제 HTTP/UI 관찰을 수행해줘. 관찰 환경이 없으면 수행한 범위와 NOT_RUN을 구분해줘.

UI가 API를 기다리거나 API가 다른 담당자를 기다리는 상태로 끝내지 말고, 이번 S01에 필요한 경계를 직접 연결해줘. 새로운 모델·MCP·대규모 프레임워크 도입을 기본 전제로 만들지 말아줘.

## 다음 단계와 완료 판정

S01만으로 ‘이력서 기반 검색 완료’를 기록하지 말아줘. SearchIntent·영속 mock 검색 작업·worker·공고 표시는 S02이고, Liner 실제 연결의 근거는 S03이야. S01이 현재 코드에서 이미 완성되어 있다면 실제 증거를 확인한 뒤 다음 미완료 단위를 선택해 진행해줘. 일부만 구현되었다면 그 부분을 재사용해 남은 연결을 완성해줘.

이후 대화·실제 PDF, Chrome 자체 폼·이력, 유사 공고 자동 준비, 조건부 자동 제출 순으로 이어가. 제품 대화 모델/API와 Liner 연결은 개발용 Claude Code 계정과 별도야. 자체 폼 성공이나 데모 자료 완성을 실제 채용사이트 지원 서비스의 출시 완료로 표시하지 말아줘. 운영 인증·파일 보관·실제 사이트 검증은 S09에서 연결해줘.

기존 요청 범위의 로컬 수정·검증은 반복 허락 없이 이어가줘. 실제 유료 호출·외부 기업 지원·배포·제출은 현재 요청과 기존 승인·계정·정책 범위를 확인해 진행하고, 이 개발 지시만으로 외부 실행을 했다고 기록하지 말아줘.

## 종료 기록

완성한 사용자 동작, 핵심 변경 파일, 실행한 검증·관찰 결과, 남은 결함·미실행, 다음 한 작업을 한국어로 보고해줘. docs/state와 작업 상태를 실제 결과에 맞게 갱신하고, 코드 위치·결정이 바뀌면 CODEMAP.md·DECISIONS.md를 맞춰줘. 별도 검토자 입력 없이도 자체 검증 근거로 완료를 판단하되, 실행하지 않은 검사를 PASS로 만들지 말아줘.
