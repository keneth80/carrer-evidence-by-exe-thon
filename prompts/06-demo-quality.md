# 단계 6 — 완주 검증과 데모 자료

## 목표

실제로 구현된 기능을 처음 사용하는 사람이 재현할 수 있게 정리하고, 제품의 핵심 흐름과 남은 범위를 정확히 보여줘. 현재 상태를 기준으로 작업하고 아직 구현되지 않은 기능을 데모 완료로 표시하지 말아줘.

## 진행

1. docs/DEMO_PLAN.md와 ACCEPTANCE.md, PROGRESS.md의 실제 상태를 확인해줘.
2. 합성 이력서 파일을 업로드해 내용 확인→공고 검색→대화형 수정→PDF→지원→이력까지 현재 완성한 범위를 재현해줘. 합성 profile을 코드에서 주입해 핵심 경로를 우회하지 말아줘.
3. 유사 공고와 자동 지원은 구현된 모드·정책 범위·자체 폼/실제 사이트 여부를 화면에서 명시해줘.
4. 실제 Liner를 연결한 경우 키·예산·모드·출처·오류·호출 결과를 확인하고 실제 관찰 범위를 기록해줘. mock을 실제 검색 성과로 표시하지 말아줘.
5. 텍스트 추출 실패, 수정 revision 충돌, 브라우저 연결 해제, 접수 불명 중 실제 지원되는 예외를 보여줘.
6. 사용자 데이터·키·계정·민감한 대화가 공개 자료에 들어가지 않도록 합성 데이터만 사용해줘.
7. 재현 명령·현재 구현 범위·알려진 제한·다음 한 작업·실제 검증을 문서로 정리해줘. 제출 형식과 마감은 최신 공식 안내를 확인해 반영해줘.

관련 검증은 남은 위험에 맞게 실행해줘. 제품 브라우저·실제 provider·실제 외부 지원을 실행하지 않았다면 각각 NOT_RUN으로 남겨줘. 데모 영상이나 제출 자료의 제작·공유·배포는 현재 요청 범위에 맞춰 수행하고, 이미 승인된 범위를 반복 확인하지 말아줘.
