# 단계 3 — 브라우저 지원과 제출 이력

## 목표

단계 2에서 확정한 PDF와 답변으로 Chrome 자체 폼에 지원하고, 접수 근거·제출 당시 문서·진행 이력을 다시 읽을 수 있게 구현해줘. 공통 계약을 통해 Ego와 외부 사이트를 뒤에 연결할 수 있어야 해.

## 구현

1. `docs/BROWSER_ADAPTERS.md`와 v0.7 제출·authorization·attempt·evidence 계약을 읽어줘. 실행 채널과 사이트 adapter의 책임을 분리해줘.
2. 현재 확장 진단에 계정/기기 연결, 작업 수신, 대상 사이트와 문서 확인, 폼 분석, 값 입력, 파일 첨부, readback, 결과 보고를 추가해줘. 필요한 권한은 실제 지원 사이트에 맞춰 제한해줘.
3. 동일 소유자의 지원 건·공고·계정·질문·답변·파일 bytes hash를 최종 확인하고 수동 제출 authorization에 결속해줘. 변경되거나 만료된 권한으로 제출하지 못하게 해줘.
4. 최초 구현은 자체 폼에서 실행하고 실제 파일이 첨부됐는지 확인해줘. 표식 진단이나 클릭 성공만으로 제출 완료를 만들지 말아줘.
5. 접수 근거를 저장하고 결과가 불명확하면 영속 상태로 남겨줘. 자동 재제출·채널을 바꾼 동일 공고 제출을 막고 조회·사용자 확인 경로를 제공해줘.
6. 지원 이력에서 회사·공고 snapshot·제출 시각·채널·문서 revision·파일·답변·권한 근거·접수 근거를 재열람하게 해줘.
7. 접수 전송 상태와 채용 진행 상태를 분리해줘. 사용자가 수동으로 추가한 외부 지원 기록도 중복 판단에 활용할 수 있게 해줘.
8. 외부 사이트의 접수 효과는 우리 DB로 취소하거나 봉인할 수 없음을 계약에 반영해줘. 자체 폼의 receipt/reconcile 보장을 외부 adapter에 그대로 사용하지 말아줘.

## 완료 기준

정상 제출·파일 readback·변경된 파일 거절·오래된 authorization 거절·중복 요청·전송 중 연결 끊김·브라우저 재시작을 검증해줘. 지원 이후 문서를 다시 수정해도 과거 제출본이 같아야 해. 사용자 A/B, 다른 공고·계정·파일로 권한 재사용이 거절돼야 해.

실제 외부 사이트 실행은 현재 사용자 요청·정책·지원 adapter 범위에 따라 별도로 수행하고 증거를 남겨줘. 이번 자체 폼 검사만으로 외부 기업 접수를 PASS로 보고하지 말아줘. 실행 환경이 없으면 브라우저 단계는 NOT_RUN/BLOCKED로 남기고 코드·서비스 검증 범위를 명시해줘.
