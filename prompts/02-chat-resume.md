# 단계 2 — AI와 대화하며 맞춤 이력서 만들기

## 목표

공고를 선택한 사용자가 AI와 대화하면, 해당 공고의 이력서가 실제로 수정 제안·변경 비교·확정 PDF까지 이어지게 구현해줘. 단계 1에서 확인된 경력과 원본을 재사용해줘.

## 구현

1. 선택 공고 snapshot, 확정 경력 revision, 기본 이력서 revision을 고정한 편집 세션을 만들어줘.
2. 공고 요건·AI 대화·이력서 미리보기/변경 비교를 함께 확인할 화면을 만들어줘. 작은 화면은 탭으로 전환하고 현재 공고·저장 상태·미확인 사실을 유지해줘.
3. 대화 provider 인터페이스를 만들고 mock으로 정상·질문·실패·늦은 응답을 재현해줘. 실제 제품 대화 모델은 별도 설정으로 연결해줘. Claude Code를 사용자 대화 런타임으로 취급하지 말아줘.
4. AI 응답은 단순 조언 외에 base revision, 변경 항목, 연결 근거, 변경 이유를 갖는 제안으로 만들어줘. 사용자 수용 시 새 이력서 revision을 저장하고 거절·부분 수용도 표현할 수 있게 해줘.
5. 표현 수정과 새로운 경력 사실을 구분해줘. 새로운 역할·기술·성과 수치가 필요하면 사용자의 확인된 진술에 연결해줘. 근거 없는 성과를 자동 확정하지 말아줘.
6. 원본 사실·이전 제출본은 유지하고 공고별 문서만 수정해줘. 오래된 제안 수용은 revision 충돌로 처리하고 재검토할 수 있게 해줘.
7. 확정 문서를 실제 PDF 파일로 생성하고 미리보기·다운로드·파일 hash·렌더 버전을 보관해줘. 텍스트만 바꾼 상태를 PDF 생성 완료로 표시하지 말아줘.
8. 지원 준비 화면에는 회사·공고·최종 파일·추가 답변을 연결해줘. 이전 회사 이름이 남아 있거나 필수 항목이 비면 확인할 수 있게 해줘.

## 완료 기준

- 사용자 대화와 수용한 제안이 실제 문서 revision에 반영된다.
- 근거 없는 수치·책임 범위가 확정 파일에 추가되지 않는다.
- 원본·이전 revision·과거 제출 파일은 변경되지 않는다.
- 지연 응답·동시 편집·오래된 제안이 최신 내용을 덮지 않는다.
- PDF의 한글·줄바꿈·페이지 경계·내용을 실제 렌더 결과로 확인하고 파일 hash가 저장된다.
- 소유권 검증이 대화·제안·문서·파일 조회에 적용된다.

`docs/ACCEPTANCE.md`와 `contracts/v0.7/`의 관련 규칙을 실제 코드·검증에 연결해줘. 새 사용자가 보는 대화 품질 검증과 mock UI 검증은 따로 기록해줘. 관련 테스트·typecheck·build 후 docs/state를 갱신해줘.
