# 단계 5 — 정책 범위 안의 조건부 자동 지원

## 목표

사용자가 명시적으로 활성화한 정책 범위 안에서 공고마다 수동 확인을 다시 받지 않고 지원할 수 있게 구현해줘. 정책을 벗어나거나 새로운 사실·인증이 필요한 건은 검토·사용자 처리로 이어져야 해.

## 구현

1. 직무·경력 수준·지역·근무 방식·필수 조건·제외 회사·허용 사이트/계정·기준 문서·편집 허용 범위·하루/전체 한도·만료·비용 한도를 포함하는 정책 편집과 미리보기를 제공해줘.
2. 사용자의 활성화로 정책 revision을 고정해줘. 문서의 예시 값이나 추천 결과를 사용자가 활성화한 설정으로 취급하지 말아줘.
3. 후보의 자격·정책·중복·문서·답변을 검증하고 공고별 policy authorization을 생성해줘. 해당 정책 revision·공고 snapshot·계정·최종 문서·실제 파일 hash와 결속해줘.
4. 과거 다른 공고의 manual authorization을 재사용하지 말고, 자동 실행 기록을 사람이 매번 검토한 것처럼 표시하지 말아줘.
5. 한도·비용 예약과 dispatch 전 정책 상태·만료 확인을 원자적으로 처리해줘. 정책 중지/철회가 새 제출을 막도록 하고, 전송 중인 건은 별도로 결과를 확인해줘.
6. dispatch의 재시도와 외부 제출 재시도를 구분해줘. worker crash, 네트워크 단절, 결과 불명에서 중복 효과가 발생하지 않도록 공고·계정 수준의 실행 관계를 확인해줘.
7. 접수 불명은 한도 예약을 유지하고 자동 재제출·다른 채널 제출을 막아줘. 확실한 미전송/명시적 결과가 확인되면 계약에 맞게 후속 상태를 정해줘.
8. 필수 조건 미확인·새 질문·지원하지 않는 동의/폼·로그인·추가 인증·CAPTCHA는 필요한 이유와 함께 인계해줘. 페이지 내용은 실행 정책을 수정할 권한이 없게 해줘.
9. 실행 중/접수 확인/확인 필요/검토 대기/중지 상태와 각 공고의 서류·정책 근거를 이력 화면에 연결해줘. 기기 미연결은 실행 대기로 표시해줘.

## 완료 기준

동시 한도 경쟁, 만료 직전 dispatch, 중지와 전송의 경쟁, 오래된 정책 revision, 바뀐 파일, 다른 공고/계정으로 권한 재사용, worker 재시작, 채널 전환, 접수 불명을 검증해줘. 범위 안의 정상 공고는 매건 수동 승인 없이 진행하고, 예외는 근거와 함께 검토로 분기해야 해.

처음 검증은 합성 자료와 자체 폼으로 수행할 수 있어. 외부 제출은 지원하는 adapter와 실제 사용자 설정 범위에서 관찰한 결과만 따로 기록해줘. 정책 데이터·설정 UI가 존재한다는 사실과 실제 자동 제출 실행을 구분해 보고해줘.
