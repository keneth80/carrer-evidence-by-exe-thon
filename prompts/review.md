# 현재 변경 검토

최근 변경을 사용자 흐름과 실제 실행 증거 중심으로 검토해줘. 먼저 변경 범위·현재 단계·미커밋 변경을 확인하고 관련 코드와 계약만 읽어줘.

## 확인할 내용

- 보유 이력서가 검색의 실제 입력인지, 합성 fixture나 고정 query가 핵심 경로를 우회하지 않는지.
- 추출 사실·사용자 확인·선호 조건·공고별 수정·최종 파일이 구분되고 출처·소유권·revision이 유지되는지.
- 대화형 제안이 실제 diff와 문서 변경으로 이어지며 근거 없는 경력·성과가 추가되지 않는지.
- 작업 저장·재시작·idempotency·lease generation·늦은 결과가 일관되는지.
- 수동/정책 authorization이 해당 공고·계정·문서·파일에 결속하고, 정책 범위의 실행에 불필요한 매건 수동 승인을 요구하지 않는지.
- 접수 불명이 자동 재제출·채널 중복·한도 반환으로 이어지지 않는지. 자체 폼 보장을 외부 사이트로 확대하지 않는지.
- 원본과 과거 제출본이 보존되고, 전송 상태와 채용 결과를 구분하는지.
- 실제 검사 없이 새 기능을 PASS로 표시하거나 계약 검사를 제품 완료로 보고하지 않는지.

결함은 사용자 영향·근거 파일·재현 조건·수정 방향 순서로 설명해줘. 먼저 해결할 실제 결함을 중심으로 보고하고, 이미 검증한 사항을 불필요하게 반복하지 말아줘. 수정까지 요청받은 범위이면 관련 로컬 수정·검증을 수행하고 상태 기록을 갱신해줘.
