# Career Evidence 시연·개발 협업 계획 v0.7

기준일: 2026.11.16 · 이 문서는 시연 계획이며 실행 결과가 아니다.

## 1. 시연에서 전달할 가치

**“이미 가진 이력서로 기회를 찾고, AI와 함께 지원 서류를 다듬고, 반복 지원과 제출 이력을 연결한다.”**

공고 검색에서 시작하는 일반적인 목록 시연보다 원본 이력서가 검색과 맞춤 편집에 실제로 영향을 주는 장면을 앞에 둔다. 자동화는 제출 수를 늘린다는 설명과 함께 사용자가 정한 조건, 확인이 필요한 예외, 실제 제출본 기록을 보여준다.

시연 데이터는 합성으로 준비한다. 다만 합성 경력 객체를 코드에서 선택하는 것으로 업로드를 대체하지 않는다. 실제 파일 등록·추출·확인 경로를 통과시킨다. 실사용자의 이력서·연락처·접수 화면은 공개 영상에 사용하지 않는다.

대화 생성·파일 변환·검색 대기 시간은 실제 편집 영상에서 압축할 수 있다. 편집한 구간을 실제 처리 속도처럼 설명하지 않는다. 시연 시점에 구현되지 않은 기능은 설계 화면으로 표시하고 완료된 것처럼 조작하지 않는다.

## 3. Liner 활용의 구체적 위치

Liner는 이력서 기반 검색 계획을 받은 공고 탐색과 공고 요건·근거 조사에 연결한다. 선택적 기업 조사도 같은 검색/근거 계층에서 다룬다. 대화형 문서 편집 모델은 별도이며, 편집 화면을 구현했다고 Liner 실호출을 했다고 표시하지 않는다.

실제 Liner 사용을 보여주려면 다음 증거가 필요하다.

- 합성 경력에서 만들어진 검색 의도와 개인정보를 제외한 입력
- 서버 어댑터의 실제 호출 모드와 작업 기록
- 응답에서 정규화한 공고·출처·확인 시각
- 화면의 추천 이유가 어떤 경력·공고 근거에 연결됐는지
- 실패·부분 결과·예산 제한을 어떻게 표시하는지

키·원문 대화 전체·불필요한 개인정보는 기록 화면에 노출하지 않는다. mock 시연만 했다면 Liner 연동 완료로 보고하지 않는다. 실시간 서비스 장애에 대비해 앞서 수행한 실제 호출 결과를 재생할 수 있으나, ‘이전에 수집한 결과’와 수집 시각을 명시한다.

## 4. 제출·자동 지원 시연 범위

브라우저 지원은 먼저 자체 테스트 폼에서 수행한다. 이 폼에 합성 자료를 입력·첨부하고 실제로 저장된 접수를 조회한다. 외부 기업 지원을 테스트 폼 시연과 동일하게 주장하지 않는다.

자동 지원은 단계 4만 끝났다면 자동 준비 모드까지 보여준다. 단계 5를 완료했다면 합성 공고와 자체 폼 대상으로 사용자 정책 활성화→공고별 권한→제출→접수 확인→한도 반영을 보여준다. 한 건은 미확인 필수 질문으로 검토 대기에 두어 예외 분기를 설명할 수 있다.

Ego를 시연할 경우 연결된 실제 실행기와 지원 경로를 검증한 뒤 사용한다. 설치 또는 공식 문서에 기능이 있다는 사실을 제품 연동 완료로 대신하지 않는다. 기본 시연 경로는 Chrome이며, 두 실행기를 동시에 구현하는 것이 첫 완주 조건은 아니다.

## 5. 현재 작업 책임 — 1인 개발

2026-11-17 사용자의 결정에 따라 개발자가 전체 기술 개발·통합·자체 검증을 맡는다. 현재 실행 지침은 `SOLO_DEVELOPMENT.md`와 `solo/TASKBOARD.md`다. 협업자의 사용자 검수·자료·발표 도움은 선택이며 아직 배정하지 않았다. 개발 착수와 완료를 협업자 API 또는 검토에 종속시키지 않는다.

과거 두 가지 분담안과 업무표는 `archive/v0.8-team/`에 보존한다. 그 자료의 제안 담당과 목표일을 현재 확정 배정으로 적용하지 않는다. 기술 담당 변경과 실제 기업 지원의 사용자 요청·정책 범위는 별개다.

## 6. 범위를 줄여야 할 때의 우선순위

1. 실제 업로드에서 시작해 경력에 따른 검색 결과를 만든다.
2. 한 공고에 대해 대화 수정과 실제 PDF 생성까지 완성한다.
3. 한 실행기로 자체 폼 지원과 당시 제출본 재열람까지 연결한다.
4. 유사 공고를 준비 목록에 넣고 검토 사유를 정확히 표시한다.
5. 조건부 자동 제출과 두 번째 브라우저·여러 ATS를 확장한다.

기업 심층 브리프, 여러 문서 형식, 모든 사이트 지원, 이메일 자동 수집은 첫 완주보다 뒤에 둔다. 이는 장기 제품에서 기능을 제외하는 결정이 아니라 구현 의존 순서다. 자동 지원은 현재 제품 명세에 포함되며 미완료 시 진행 상태에 그대로 남긴다.

## 7. 공개 전 확인

새 환경 재현, 실제 제품 경로, 출처·시각, 이력서 버전, mock/live 구분, 실패·미확인 표시를 확인한다. 실제 실행 결과는 `reports/VALIDATION.md`에 기록한다. 제출 마감·요구 파일·공식 행사 조건은 팀이 받은 최신 안내와 대조하고 과거 일정 숫자를 코드 실행 차단 조건으로 사용하지 않는다.
