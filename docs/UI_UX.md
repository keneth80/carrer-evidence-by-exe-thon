# Career Evidence 화면·상태 설계 v0.7

기준일: 2026.11.16 · 구현할 현재 화면 기준 · 완성된 UI로 오해하지 않도록 `state/PROGRESS.md`와 함께 읽는다.

## 1. 정보 구조

주 메뉴는 **공고 찾기 / 내 이력서 / 지원 이력 / 자동 지원**으로 구성한다. 로그인·연결·비용 설정은 보조 메뉴다. 첫 방문의 주 행동은 ‘이력서 등록하기’이며, 등록 후에는 최근 검색·편집 중인 이력서·확인이 필요한 지원을 보여준다.

아래 경로는 프런트엔드 화면 경로 제안이다. HTTP API와 상태 enum은 `../contracts/v0.7/`의 계약을 따른다. 화면용 한글 상태를 DB enum으로 그대로 저장하지 않는다.

| ID | 화면 | 경로 제안 | 주 행동 |
| --- | --- | --- | --- |

## 2. 공통 표현 원칙

- 첫 화면에서 경력을 모두 다시 입력시키지 않는다. 추출 결과를 확인하고 필요한 정보만 보충한다.
- 검색 결과에는 추천 근거와 확인할 조건을 함께 보여준다. 적합도 수치를 합격 가능성으로 표현하지 않는다.
- 서비스 내부의 모델명·lease·CAS·hash는 일반 사용자 흐름의 주 문구로 쓰지 않는다. 사용자는 파일명, 수정 시각, 버전, 제출 대상을 확인한다.
- 로딩 중에는 실제 단계와 취소 가능 여부를 표시한다. 완료되지 않은 작업을 100%로 채우지 않는다.
- 실패는 입력 문제·연결 문제·확인 필요를 구분하고 다음 행동을 제시한다.
- mock은 ‘합성 예시’, 실제 API로 수집한 데이터는 출처·확인 시각으로 표시한다.
- 키보드 이동·포커스·스크린리더 상태 알림을 제공하고 의미를 색 하나에만 맡기지 않는다.
- 모바일에서는 긴 3열 편집 화면을 공고/대화/문서 탭으로 전환하고, 수용·되돌리기 동작의 상태를 유지한다.

## 3. U01 시작·이력서 등록

**목적:** 사용자가 가진 이력서를 서비스의 출발점으로 만든다.

상단에는 ‘이력서에서 맞는 기회를 찾아드릴게요’와 지원 형식을 짧게 표시한다. 텍스트 PDF 업로드 영역 아래에 ‘텍스트로 붙여넣기’를 제공한다. DOCX·스캔 PDF를 지원하지 않는 초기 단계에서는 이를 업로드 전에 알려준다. 파일 제한은 서버 설정과 같은 값으로 표시한다.

파일을 고르면 이름·형식·크기를 보여주고 업로드를 시작한다. 완료 후 내용 추출 진행을 표시하고 U02로 이동한다. 합성 데모 파일은 ‘예시 이력서로 체험’에서 다운로드 또는 선택할 수 있지만, 실제 업로드·추출 경로를 거쳐야 한다.

| 상태 | 표시·동작 |
| --- | --- |
| 처음 방문 | 파일 등록과 텍스트 입력을 주 행동으로 제공 |
| 업로드 중 | 전송 상태, 취소·재시도 가능 여부 표시 |
| 추출 중 | ‘내용을 읽고 있어요’; 새로고침 후 같은 작업 재조회 |
| 텍스트 없음 | ‘텍스트를 읽지 못했어요’; 붙여넣기 또는 다른 파일 선택 |
| 지원하지 않는 형식 | 실제 허용 형식을 안내; 빈 결과로 완료 처리하지 않음 |
| 소유권·세션 문제 | 접근 가능한 계정으로 다시 연결; 다른 사용자 문서 정보 노출 없음 |

## 4. U02 추출 내용 확인

왼쪽은 원문 페이지 또는 붙여넣은 내용, 오른쪽은 구조화된 경력 목록이다. 항목을 선택하면 해당 원문 구간을 강조한다. 페이지를 특정할 수 없으면 없는 위치를 만들어 보여주지 않는다.

확인 대상은 경력 기간·회사·역할·기술·프로젝트·기여·성과다. 각 항목은 ‘원문에서 추출 / 사용자가 수정 / 추가 확인 필요’를 구분한다. 연락처는 별도 구역에 두어 검색용 정보와 혼합하지 않는다.

주 행동은 **‘확인한 내용으로 공고 찾기’**다. 희망 직무·지역·근무 방식은 짧은 보조 입력으로 받고 나중에 바꿀 수 있다. 저장 시 확정 경력 revision을 만든다. 미확인 항목을 자동으로 확정하거나 ‘없음’으로 바꾸지 않는다.

원본을 바꿨다면 새 문서로 등록하고, 어느 내용을 검색에 쓸지 선택하게 한다. 이전 제출 이력에 사용된 경력 revision은 유지한다. 여러 탭에서 동시에 수정하면 현재 버전을 다시 불러오거나 변경을 비교하도록 한다.

## 5. U03 공고 추천·상세

상단에는 검색에 사용한 이력서 버전과 직무·지역·근무 방식 요약을 표시한다. 사용자는 ‘검색 기준 보기’에서 경력 근거와 희망 조건을 확인할 수 있다. 검색어 입력은 보조 기능으로 둔다.

카드에는 회사·직무·위치·근무 방식·고용 형태·확인 시각·원문 링크를 제공한다. 아래에 ‘추천한 이유’와 ‘확인할 조건’을 각각 1~3개 보여준다. 예: ‘프론트 구조 설계 경험과 연결’, ‘팀 리딩 요건에 해당하는 경력 있음’, ‘급여 범위가 공개되지 않음’. 예시는 실제 사용자 판단 결과로 저장하지 않는다.

상세에서는 공고 요구와 확정 경력을 나란히 비교한다. 주 행동은 **‘이 공고에 맞춰 이력서 수정’**이다. 관심 저장, 원문 열기, 필요 시 회사 조사 요청은 보조 행동이다.

| 상태 | 표시·동작 |
| --- | --- |
| 검색 중 | 사용한 기준과 진행 상태, 이미 저장된 결과 표시 |
| 빈 결과 | 기준 유지 상태에서 범위 조정·새 탐색 제안 |
| 부분 결과 | 확인된 결과부터 표시하고 실패한 조사 범위 명시 |
| 조건 변경 | 저장 근거 재평가 결과와 새 탐색 필요 여부 구분 |
| 오래된 결과 | 해당 검색의 경력·조건 버전을 표시; 최신 결과를 덮지 않음 |
| 이미 지원 | 제출 시각·상태를 보여주고 이력으로 이동 |
| 접수 불명 | 재지원 버튼보다 ‘접수 확인’ 행동을 우선 |

## 6. U04 대화형 맞춤 편집

### 6.1 데스크톱 구성

세 영역은 **공고 요구 / AI 대화 / 이력서 미리보기**다. 상단에 회사·직무와 현재 문서 버전을 고정한다. 편집 중 공고를 바꾸는 동작은 새 편집 세션을 만들며 기존 내용을 덮어쓰지 않는다.

공고 요구를 선택하면 연결된 경력 문장을 강조한다. 대화에는 일반 답변과 변경 제안을 구분한다. 변경 제안 카드에는 대상 구역, 변경 전·후, 변경 이유, 근거, 수용·거절 버튼을 둔다.

### 6.2 대화 예시와 실제 변경

사용자가 ‘리딩 경험을 더 드러내줘’라고 하면 AI는 확인된 사실에서 먼저 수정안을 만든다. 담당 범위가 부족하면 한 번에 필요한 질문을 좁혀 묻는다. 새로운 성과 숫자를 입력할 때는 사용자가 확인해야 경력 사실로 반영한다.

단순 조언만 대화창에 남기고 문서가 바뀌지 않는 구현은 완료가 아니다. ‘적용됨’ 표시와 실제 revision 변화, 미리보기 내용이 일치해야 한다.

### 6.3 상태와 충돌

| 상태 | 표시·동작 |
| --- | --- |
| 첫 진입 | 공고 핵심 요구와 추천 편집 방향, 사용자가 원하는 강조점 선택 |
| 답변 생성 중 | 입력한 메시지는 유지; 아직 수용하지 않은 제안은 미적용 |
| 새 사실 확인 | ‘이 내용을 경력 정보에 추가할까요?’와 원문/대화 근거 |
| 근거 없는 주장 | 확인 질문 또는 제거 제안; 자동 확정 금지 |
| 제안 적용 | 변경 전후 비교와 새 버전 표시 |
| 기반 버전 변경 | ‘다른 변경이 있어 다시 비교가 필요해요’; 자동 덮어쓰기 금지 |
| 생성 실패 | 입력 메시지·기존 문서 보존, 실패한 단계만 재시도 |
| 사용자 되돌리기 | 이전 내용을 새 revision으로 복원하고 기록 유지 |

하단 주 행동은 **‘최종 제출본 확인’**이다. 확인되지 않은 사실이나 필수 항목이 남아 있으면 해당 위치로 이동하게 한다.

## 7. U05 최종 제출본 확인

최상단에 회사·직무·지원 사이트를 표시한다. 실제 PDF 미리보기, 파일명·페이지 수·생성 시각, 추가 질문 답변, 사용할 계정·실행기를 함께 확인한다. HTML 편집 미리보기만으로 PDF 검토를 대체하지 않는다.

수동 지원에서는 ‘이 내용으로 지원’을 선택한 내용에 맞춰 실행 권한을 만든다. 누른 뒤 파일이나 답변이 바뀌면 새 내용을 확인하도록 한다. 정책 자동 지원 건은 ‘자동 지원 설정에 따라 준비됨’으로 표시하고 사용자가 직접 검토한 것으로 표기하지 않는다.

브라우저 미연결은 파일 검토 실패와 다른 상태다. 검토한 내용을 보존하고 연결 후 현재 공고·계정·파일을 재확인한다. 파일 생성 실패, 회사명 불일치, 미확인 필수 문항은 제출 동작을 대기시킨다.

## 8. U06 브라우저 지원 패널

패널에는 회사·직무·사용할 이력서, 연결된 사이트·계정, 현재 단계를 표시한다. 단계는 ‘페이지 확인 → 항목 입력 → 파일 첨부 → 입력 내용 확인 → 제출 → 접수 확인’으로 보여준다.

첫 구현은 Chrome 자체 테스트 폼이다. 공식 `activeTab`은 사용자 동작에 따른 임시 접근이므로 여러 사이트에서 계속 실행하는 권한과 동일하게 취급하지 않는다. 사이트별 접근 권한과 실행기 연결은 자동 지원 단계에서 따로 구현한다. [Chrome 공식 문서](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)

로그인·추가 인증·사용자가 직접 확인해야 하는 문항은 ‘직접 확인이 필요해요’로 전환하고 해당 페이지를 유지한다. 비밀번호·인증코드를 대화창에 붙여 넣게 하지 않는다. 재개할 때 계정과 대상이 그대로인지 확인한다.

전송 직후 연결이 끊기면 ‘접수 여부를 확인 중입니다’로 기록한다. ‘다시 지원’ 버튼으로 자동 재전송하지 않는다. 웹과 확장 모두 같은 지원 상태를 조회한다.

## 9. U07 지원 이력

목록에는 회사·직무·지원 시각·제출 상태·채용 진행 상태를 표시한다. 사용자는 상태, 기간, 자동/직접 지원으로 필터링한다. 세부 화면에서 다음 자료를 열어볼 수 있다.

- 지원 당시 공고와 원문 링크
- 실제 제출한 이력서와 추가 답변
- 직접 확인 또는 자동 지원 설정에 따른 실행 기록
- 접수 근거와 확인 시각
- 면접·결과·메모 등 채용 진행 이벤트

‘최신 이력서’와 ‘당시 제출 이력서’를 구분한다. 제출 후 편집한 문서가 과거 상세에 바뀌어 보이지 않도록 한다. 사용자가 직접 지원한 건을 추가하는 행동도 제공한다.

‘이 지원과 비슷한 공고 찾기’가 U08의 진입점이다. 접수 여부가 불명확한 기준 건은 그 상태를 보여주며, 기준 선택이 중복 제출을 허용하는 것으로 해석되지 않게 한다.

## 10. U08 유사 공고·자동화 설정

기준 공고와 이력서 버전을 상단 카드로 고정한다. 모드는 ‘추천만 받기 / 지원서 자동 준비 / 조건에 맞으면 자동 지원’ 세 가지를 설명과 함께 선택한다. 자동 제출은 기본으로 켜지지 않는다.

설정 항목은 직무·경력 수준·고용 형태·지역·근무 방식, 필수 처우 조건, 제외 회사, 허용 사이트, 사용할 계정, 문서 수정 범위, 일일·전체 건수, 비용 한도, 종료 시각이다. 필수로 정한 조건이 공고에서 확인되지 않으면 어떻게 대기시키는지 요약한다.

문서 옵션은 ‘이 파일 그대로 사용’과 ‘확인한 경력 안에서 공고별 수정’이다. 후자의 설명에는 강조 순서·표현 변경 범위와 새 사실 확인이 필요한 경우를 포함한다.

활성화 전에 예상 동작을 요약한다. 예시 후보를 보여줄 때 실제 검색 결과인지 합성 예시인지 표시한다. 사용자가 확인한 정책 revision을 활성화하고 설정을 바꾸면 새로운 revision과 적용 범위를 표시한다. 단순 저장과 자동 제출 활성화는 다른 행동이다.

## 11. U09 진행·예외함

상단에는 실행 상태, 남은 기간, 오늘·전체 건수, 예약 중인 건수, 연결된 기기를 표시한다. 발견·준비·접수 확인·확인 필요를 나누어 보여준다. 접수 결과가 불명확한 건은 완료 건수에 포함하지 않는다.

목록에는 공고, 유사한 이유, 정책 판정, 사용한 문서, 현재 상태, 필요한 사용자 행동을 보여준다. 확인할 이유는 구체적으로 쓴다. 예: ‘필수 근무 지역을 확인할 수 없음’, ‘이 회사의 추가 질문에 답변 필요’, ‘브라우저 연결 대기’, ‘접수 내역 확인 필요’.

일시 중지는 신규 지원을 멈춘다. 이미 전송 중인 건에는 ‘전송 중인 지원은 결과를 확인합니다’를 표시한다. 중지했다고 외부 전송이 취소된 것으로 보여주지 않는다. 재개 시 정책·한도·기한·공고 상태를 다시 평가한다.

사용자가 한 건을 수정했을 때 그 수정으로 자동 지원 정책 전체가 바뀌지 않는다. 반복 기준을 바꾸려면 정책 편집으로 이동한다.

## 12. U10 버전·연결 설정

이력서 보관함은 원본, 확정 경력, 공고별 제출본을 구분한다. 이름과 수정 시각, 사용한 공고를 보여주고 실제 과거 파일을 내려받을 수 있게 한다. 개인정보가 포함된 파일을 공개 링크로 자동 전환하지 않는다.

연결 화면에서는 실행기 이름, 마지막 연결 시각, 연결된 기기, 지원하는 사이트를 표시한다. Ego 방식은 설치된 컴퓨터에서 실행할 연결이 필요하며, 원격 서버에 가이드만 추가했다고 연결 완료로 표시하지 않는다. [Ego 공식 연결 문서](https://www.egolite.app/document/en/docs/custom-agent-harness)

사용자 PC가 꺼져 있거나 실행기가 연결되지 않았다면 대기열을 보존하고 연결 대기로 표시한다. ‘24시간 자동 지원 중’처럼 실제 실행 상태와 다른 표현을 사용하지 않는다.

## 13. 화면 완료 기준

각 화면은 정상·빈 값·실패·미확인·오래된 버전 상태를 재현할 수 있어야 한다. 합성 fixture를 이용하더라도 업로드·추출·대화 적용·문서 생성·지원 기록의 실제 제품 경로를 통과한다. 코드 및 브라우저 검증 결과는 `ACCEPTANCE.md`와 `reports/VALIDATION.md`에 구분해서 남긴다.
