## 3. 검증 범위의 한계

이번 작업은 런타임 코드를 바꾸지 않았으므로 v0.7의 전체 npm/HTTP/DB/계약 검사를 반복하지 않았다. 이전 검사 결과는 [v0.7 검증 기록](VALIDATION.md)에 별도로 보존한다. 이번 문서·표 검증을 실제 이력서 등록·대화형 수정·브라우저 지원·자동 제출의 완료 증거로 사용하지 않는다.

현재 제품 API·영속 worker·실제 Liner·브라우저 제출의 미구현/미검증 상태는 기존과 같다. 새 사용자 흐름의 인수는 [제품 인수 기준](../ACCEPTANCE.md)에 따라 실제 구현 뒤 수행해야 한다. 외부 메시지, 실제 기업 지원, 대회 제출, 배포는 이번 작업에서 실행하지 않았다.

11/16~25 일정은 이전 자료의 제출 안내를 바탕으로 한 협의용 목표다. 최신 행사 공지와 실제 가용시간은 이번 문서 작업에서 새로 검증하지 않았다. T02에서 최신 안내를 확인하고, 특히 11/22~23의 자동화 작업은 가용시간에 맞춰 재배분한다.

## 4. 최종 패키지 확인

문서 진입 경로·상대 링크·기존 기준 파일은 `node scripts/check-integration.mjs`로 확인한다. 배포 ZIP에는 `MANIFEST.sha256`과 기존 통합 개발 기반을 포함하고, node_modules·dist·DB·실제 비밀 값·임시 렌더 이미지는 포함하지 않는다. 최종 파일 묶음의 전체 SHA-256과 ZIP CRC를 배포 전에 대조한다. 최종 실행 결과는 패키지 작성 결과와 함께 제공한다.
