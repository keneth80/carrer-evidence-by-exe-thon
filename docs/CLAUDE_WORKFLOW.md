# Claude Code에서 시작하고 이어가기 — v0.7

작성일: 2026.11.16. 현재 통합 패키지의 개발 절차다. 프로젝트 지침·상태·단계별 일반 Markdown 프롬프트를 사용한다. 추가 skill이나 MCP 설치를 기본 전제로 두지 않는다.

## 새 프로젝트에서 시작

압축을 새 폴더에 풀고 루트 README의 Node·npm 환경을 준비한다. `package.json`과 `CLAUDE.md`가 있는 폴더에서 현재 설치한 Claude Code를 실행한다.

```bash
claude --version
claude
```

Claude Code 설치가 필요한 경우 [공식 설치 안내](https://code.claude.com/docs/en/setup)를 확인한다. 프로젝트는 사용자의 모델·계정·전역 권한 설정을 강제로 바꾸지 않는다.

첫 요청은 다음과 같다.

```text
CLAUDE.md와 prompts/00-start.md를 읽고 실행해줘.
보유 이력서 등록부터 내용 확인, 확정 경력 기반 검색, 영속 작업 처리, 공고 표시까지 첫 사용자 흐름을 구현·검증해줘.
현재 통합 v0.7을 기준으로 하고, 실제 상태와 다음 작업을 docs/state에 기록해줘.
```

`prompts/`는 파일을 읽도록 요청하는 방식이다. 별도 slash command 등록이 필요하지 않다. 루트 `CLAUDE.md`의 프로젝트 지침 로드 방법과 범위는 공식 메모리 문서를 따른다.[1]

## 기존 저장소가 있을 때

이번 패키지는 처음 시작할 수 있게 구성했지만, 별도 기존 저장소가 있다면 옆 폴더에 풀고 필요한 내용을 선택적으로 적용한다. 사용자 코드·미커밋 변경·인증·DB·라우팅을 먼저 확인한다.

```text
현재 저장소를 유지하면서 별도로 압축 해제한 Career Evidence 통합 v0.7을 참고해줘.
현재 코드와 v0.7 제품 명세·계약·결정 기록을 비교하고, 필요한 파일만 선택적으로 반영해줘.
기존 작업을 덮어쓰지 말고 이력서 등록 → 내용 확인 → 이력서 기반 검색에서 가장 작은 미완료 흐름을 구현·검증해줘.
통합 패키지의 로컬 경로를 알 수 없다면 그 경로만 확인해줘.
```

기존 코드가 이미 다른 구조를 갖추었다면 현재 구조를 우선 활용하고 CODEMAP·실행 명령을 갱신한다. 새 프레임워크나 DB 초기화는 필요성과 영향 확인 없이 추가하지 않는다.

## 작업별 진입 파일

| 목적 | 요청 |
| --- | --- |
| 처음 시작 | `prompts/00-start.md를 실행해줘.` |
| 1. 이력서→검색 | `prompts/01-resume-search.md의 미완료 항목을 구현해줘.` |
| 2. 대화형 수정→PDF | `prompts/02-chat-resume.md를 실행해줘.` |
| 3. 브라우저→이력 | `prompts/03-browser-history.md를 실행해줘.` |
| 4. 유사 공고→자동 준비 | `prompts/04-similar-jobs.md를 실행해줘.` |
| 5. 조건부 자동 제출 | `prompts/05-auto-apply.md를 실행해줘.` |
| 6. 데모·품질 | `prompts/06-demo-quality.md를 실행해줘.` |
| 새 대화에서 재개 | `prompts/resume.md를 읽고 다음 한 작업을 완료해줘.` |
| 최근 변경 검토 | `prompts/review.md 기준으로 최근 변경을 검토해줘.` |

각 작업은 구현·관련 검증·상태 기록까지 묶는다. 첫 요청에서 전체 로드맵을 한꺼번에 처리하기보다 현재 사용자 흐름이 실제로 동작하는지 확인한 뒤 이어간다. 현재 범위 안에서 해결할 수 있는 수정은 불필요한 확인 요청 없이 진행한다.

## 문맥과 사용량 관리

`CLAUDE.md`에는 공통 규칙만 두었다. 전체 계약과 과거 PDF를 자동 import하지 않고 CODEMAP과 단계 프롬프트에서 필요한 부분을 찾는다. 관련 파일을 `rg`로 좁혀 읽고, 긴 로그는 실패 원인과 재현 조건 중심으로 정리한다.[1][2]

같은 폴더의 최근 대화를 이어가려면 다음 명령을 사용할 수 있다.[3]

```bash
claude -c
```

새 세션을 쓰려면 HANDOFF와 `prompts/resume.md`를 기준으로 재개한다. 긴 대화를 정리할 때는 완료 범위·변경 파일·실제 검증·미완료 작업이 유지되도록 요청한다. 메모리 파일과 지침은 개발을 돕는 문맥이며, 실제 권한·소유권·중복 방지는 런타임 코드와 DB 제약으로 구현한다.[1][2]

## 기록 파일의 역할

- `state/PROGRESS.md`: 현재 구현 상태와 증거. 과거 테스트 수를 새 기능의 검증으로 재사용하지 않는다.
- `state/HANDOFF.md`: 다음 한 작업, 관련 파일, 재현 명령, 남은 문제.
- `../DECISIONS.md`: 사용자 요구·기본 선택·변경한 결정과 이유.
- `CODEMAP.md`: 기능별 실제 코드 진입점과 아직 만들지 않은 부분.
- `reports/VALIDATION.md`: 패키지 작성 시 실제 실행한 검사와 범위.
