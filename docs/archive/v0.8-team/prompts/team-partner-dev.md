# 협업자 개발 담당 시작 — 팀 패키지 v0.8

이 요청은 두 사람이 개발을 나누는 안에서 API·DB·검색·worker 영역을 구현하기 위한 지시야. 사용자 요청과 합의된 담당을 우선하고, 현재 제품 계약 v0.7을 유지하면서 필요한 사용자 흐름을 완성해줘.

## 확인할 자료

루트 CLAUDE.md, DECISIONS.md, docs/team/TEAM_WORKPLAN.md, docs/team/tasks.json, docs/state/PROGRESS.md, docs/state/HANDOFF.md, docs/CODEMAP.md를 읽어줘. 단계 1은 `prompts/01-resume-search.md`와 필요한 v0.7 모델·API를 함께 봐줘. 모든 과거 자료를 일괄 읽을 필요는 없어.

업무표의 확정 담당 또는 이번 사용자 요청을 우선해줘. JSON은 초기 작업 기준이고 XLSX와 자동 동기화되는 시스템이 아니야. 현재 저장소·미커밋 변경과 이미 구현된 코드를 먼저 확인해줘.

## 첫 담당 흐름

T05 → T06 → T08 순서의 서버 경로를 연결해줘.

1. 인증된 principal·workspace 소유 범위와 명시적인 DB migration을 구현해줘. v0.4 baseline과 기존 자료를 보존하고 DB reset으로 해결하지 말아줘.
2. 텍스트 PDF/붙여넣기 등록, 실제 bytes hash, 원문 위치, 추출 실패 복구, 사용자 확인 후 경력 revision을 연결해줘.
3. 확정 경력과 별도 선호 조건에서 SearchIntent를 만들고 영속 task·worker·저장 검색 결과로 이어줘.
4. 서로 다른 합성 파일이 서로 다른 검색 계획을 만드는지, 중복 요청·재시작·오래된 lease·교차 소유 범위 접근을 처리하는지 검증해줘.
5. 기본 mock으로 로컬 흐름을 완성할 수 있어. 실제 Liner 연결은 사용자가 준비한 키·예산·기존 허용 범위 안에서 검증하고 실제 호출 근거를 구분해줘.

API가 연결되기 전에도 개발자가 화면을 만들 수 있도록 성공·실패·처리 중 응답과 호출 예제를 먼저 정리해줘. 공유하는 공개 필드와 상태 이름을 임의로 따로 만들지 말아줘.

## 후속 영역과 경계

지원 revision·권한·attempt·접수 이력, 고정 seed 유사 검색, 정책·한도·중지·worker는 이후 단계야. 개발자의 대화 편집·PDF 모듈을 공용 router·worker·파일 저장에 연결해줘. 신규 서비스 경로는 실제 생성 후 CODEMAP에 반영해줘.

공통 router·DB·Schema를 수정할 때 관련 타입과 예제도 함께 맞춰줘. 다른 개발 세션의 변경을 보존하고, 충돌은 변경 의도를 확인해 통합해줘. 계획만 작성하지 말고 이번에 맡은 한 흐름의 코드와 검증까지 진행해줘.

## 완료·인계

작업 ID, 입력/출력/대표 오류, DB 전환, 호출 예제, 실행한 검증, 미실행 항목, 개발자가 연결할 부분, 다음 작업을 한국어로 보고해줘. 상태 파일은 합의한 통합 방식으로 갱신하고 기존 계약 검사 PASS를 실제 브라우저 지원 성공으로 바꾸지 말아줘. 실제 기업 제출이나 외부 메시지 전송은 이 개발 지시의 실행 결과로 만들지 말아줘.
