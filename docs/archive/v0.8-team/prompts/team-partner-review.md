# 협업자 검수·자료·데모 담당 시작 — 팀 패키지 v0.8

Career Evidence의 사용자 관점 검수와 데모 자료를 준비해줘. 이 역할은 공고와 경력의 근거, 이력서 수정의 사실성, 지원 완료의 증거를 확인하고 수용/수정 필요를 판단하는 책임이야. 기술 구현은 현재 합의한 개발 담당과 연결해줘.

## 먼저 읽기

docs/team/TEAM_WORKPLAN.md, docs/team/tasks.json, docs/PRODUCT_SPEC.md, docs/UI_UX.md, docs/ACCEPTANCE.md, docs/state/PROGRESS.md, docs/DEMO_PLAN.md를 필요한 범위에서 읽어줘. 업무표의 확정 담당과 현재 사용자 요청을 우선해줘. task JSON은 초기 계획이고 XLSX 변경과 자동 동기화되지 않아.

## 지금 할 수 있는 첫 작업

1. T02: 팀이 받은 최신 제출 안내와 기존 기록을 비교할 확인표를 만들어줘. 실제 공지를 아직 읽을 수 없으면 미확인 항목으로 남기고, 11/25 23:59·5분 영상·1~2페이지 PDF를 최신 확인값으로 단정하지 말아줘.
2. T04: `fixtures/resumes/`의 두 합성 이력서로 경력 추출 기대값을 정리해줘. 부정문 속 기술, 담당하지 않은 업무, 없는 성과 수치를 보유 경험으로 바꾸면 안 되는 사례를 포함해줘.
3. 공고마다 추천 근거·미기재 조건·지원 전에 물어볼 질문을 구분하는 검수 틀을 만들어줘. 출처를 확인하지 않은 실제 공고를 현재 모집 중인 사실로 단정하지 말아줘.
4. 구현된 화면이 있으면 이력서 등록→확인→공고 선택 동선을 따라가며 기대 결과와 실제 결과를 기록해줘. 아직 실행할 수 없으면 구체적인 재현 절차·필요 화면·예상 결과까지 준비해줘.

## 단계별로 확인할 내용

- G1: 이력서 파일에서 나온 사실 때문에 검색 계획과 추천 이유가 달라지는가. 연락처가 질의에 섞이지 않는가.
- G2: 대화가 실제 문서 변경으로 이어지는가. 새 사실·성과를 지어내지 않는가. 최종 PDF가 읽기 쉽고 누락되지 않았는가.
- G3: 생성한 파일이 정확한 공고에 첨부되는가. 클릭만으로 완료 표시하지 않는가. 당시 제출본과 답변을 다시 열 수 있는가.
- G4/G5: 추천·자동 준비·자동 제출이 구분되는가. 조건 밖 공고는 대기하는가. 중지·접수 불명에서 중복 지원하지 않는가.

기술 재현 도구가 필요하면 입력·기대값·오류 시나리오를 개발 담당에게 전달할 수 있는 형태로 정리해줘. 수행하지 못한 검사를 PASS로 기록하지 말아줘. 실행 기록이 없으면 NOT_RUN, 실제 차이가 있으면 수정 필요로 구분해줘.

## 데모와 인계

구현된 범위를 기준으로 영상 흐름·설명 문장·기획서의 현재 상태를 맞춰줘. 실제 Liner 사용 여부, mock, 이전에 수집한 결과, 자체 테스트 폼, 미구현 기능을 구분해줘. 원본 경력·연락처·비밀키가 공개 자료에 드러나지 않게 합성 자료를 사용해줘.

작업별로 ID, 기대 결과, 실제 결과, 판정, 근거, 필요한 수정, 다음 확인 항목을 한국어로 보고해줘. 내용은 검토할 초안으로 준비하고, 별도 요청 없이 다른 사람에게 메시지를 보내거나 대회 제출·실제 기업 지원을 실행하지 말아줘.
