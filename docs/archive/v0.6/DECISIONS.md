# 제품 흐름 정정 결정 기록

2026.11.16. v0.4 계약과 v0.5 starter의 원본은 보존한다. 다음 구현 계약을 위한 기록이며, 자동 지원 실행을 활성화한 문서가 아니다.

## 사용자가 명확히 요청한 제품 방향

| ID | 방향 |
| --- | --- |
| F01 | 최초 입력은 사용자가 이미 가진 이력서다. 이력서를 기반으로 공고를 찾아 노출한다. |
| F02 | 선택 공고에 맞게 AI와 대화하며 이력서 자체를 수정한다. |
| F03 | 확정한 이력서로 Ego 또는 Chrome 확장을 통해 지원한다. |
| F04 | 어느 공고에 어느 이력서로 지원했는지 이력을 관리한다. |
| F05 | 지원한 공고와 비슷한 공고 탐색·자동 지원을 제품 기능에 포함하는 방향을 검토한다. |

## 이번 검토의 구현 제안

| ID | 제안 | 이유 |
| --- | --- | --- |
| P01 | 원본·확정 경력·공고별 이력서·실제 파일을 분리 | 사실 보존과 과거 제출본 재열람 |
| P02 | 대화 수정은 base revision과 diff를 갖는 제안 | 새 사실·표현 수정·사용자 수용을 구분 |
| P03 | 검색의 입력은 확정 경력·조건에서 만든 SearchIntent | 고정 query·합성 프로필 선택 중심 흐름 수정 |
| P04 | 추천/자동 준비/조건부 자동 지원 모드 분리 | 사용자가 원하는 자동화 범위와 제출 권한을 명시 |
| P05 | 자동 지원은 opt-in 정책·한도·만료·지원 대상과 공고별 authorization | 과거 한 건의 승인을 여러 기업에 재사용하지 않음 |
| P06 | 동일 공고 지원 불명은 재제출·타 채널 실행도 대기 | 외부 사이트 중복 효과 방지 |
| P07 | 공통 ApplyAdapter 아래 Ego와 Chrome 실행기 | 실행 기술 변경에도 파일·승인·이력을 유지 |
| P08 | 최초 실증은 실행기1개·명확한 테스트 대상 | 완주 흐름 검증에 집중 |
| P09 | 외부 ATS와 자체 receipt/reconcile을 분리 | 우리 DB가 외부 접수를 취소·봉인할 수 없음 |
| P10 | 대화형 맞춤 이력서를 기업 심층 브리프보다 앞선 핵심 흐름에 배치 | 사용자가 원하는 직접적인 지원 준비 가치 |

## 아직 정하지 않은 것

지원할 최초 채용사이트, Ego/Chrome 중 첫 실행기, 사용자 파일 형식의 초기 범위, 대화 모델·API, 자동 지원의 실제 회사·급여·건수·기간·비용 한도는 구현·사용자 설정 단계에서 정한다. 예시 값은 사용자 승인이나 실행 명령이 아니다.

## 현재 작업에서 하지 않은 것

v0.5 코드 수정, 새 DB migration 적용, 신규 OpenAPI/JSON Schema 확정, 실제 이력서 업로드, Ego 설치·로그인, 외부 기업 지원, 자동 지원 정책 활성화, 메일 접근, 배포를 수행하지 않았다.
