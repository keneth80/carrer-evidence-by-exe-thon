# Claude Code에서 시작하고 이어가는 방법

작성일: 2026.11.15. 이 문서는 현재 Claude Code 사용 환경을 유지하면서 이 프로젝트를 개발하는 절차다. 새 모델 구독·Anthropic API 키·MCP 설치를 요구하지 않는다. 제품의 Liner API 키는 별도로 관리하며 mock 개발에는 필요하지 않다.

## 1. 새 프로젝트로 시작

압축은 독립된 개발 폴더에 푼다. 루트 README의 Node 버전·설치 명령으로 의존성을 준비한 뒤, **package.json과 CLAUDE.md가 있는 폴더**에서 실행한다.

```bash
claude --version
claude
```

설치가 되어 있지 않으면 [공식 설치 안내](https://code.claude.com/docs/en/setup)를 따른다. 이 킷이 사용자의 전역 Claude 설정이나 인증 정보를 변경하지는 않는다.

Claude Code에 다음 문장을 입력한다.

```text
CLAUDE.md와 prompts/00-start.md를 읽고 실행해줘. 현재 구현된 부분을 보존하면서 환경을 점검하고, 다음 미완료 사용자 흐름 한 개를 구현·검증해줘. 기본 mock 모드를 유지하고, 결과와 다음 작업을 docs/state에 기록해줘.
```

`prompts/`는 일반 Markdown 파일이다. 별도 slash command 설치 없이 파일을 읽으라고 요청하면 된다. 루트 CLAUDE.md는 프로젝트 지침으로 사용되며, 로드 여부는 세션의 `/context` 또는 `/memory`에서 확인할 수 있다.[1]

## 2. 기존 채용 에이전트 저장소에 연결

기존 프로젝트 위에 압축을 덮어쓰지 않는다. 킷을 옆 폴더에 두고 기존 저장소에서 다음 요청을 사용한다.

```text
현재 저장소를 유지하면서 별도로 압축 해제한 Career Evidence Claude 스타터킷을 적용해줘. 먼저 기존 변경사항·실행 명령·프레임워크·DB·구현 상태를 확인하고, 킷의 CLAUDE.md와 DECISIONS.md, v0.4 계약을 비교해줘. 적용할 파일만 선택적으로 가져오고 기존 파일과 충돌하는 지침은 이유를 기록해 정리해줘. 현재 코드로 충족한 기능을 재구현하지 말고, 검색→비교→근거 확인에서 가장 작은 미완료 흐름 한 개를 구현·검증해줘. 킷 폴더의 실제 경로가 없으면 그 경로만 물어봐줘.
```

기존 의존성·인증·라우팅을 확인하기 전에 새 프레임워크를 설치하거나 저장소를 초기화하지 않는다. 프로젝트 구조가 다르면 CODEMAP과 실행 명령을 실제 저장소에 맞게 갱신한다. 사용자 로컬 변경과 Git 이력은 보존한다.

## 3. 작업 단위

| 상황 | 입력할 요청 |
| --- | --- |
| 최초 시작 | `prompts/00-start.md를 실행해줘.` |
| 기반 연결 | `prompts/01-foundation.md의 남은 항목을 구현해줘.` |
| 핵심 제품 흐름 | `prompts/02-search-analysis.md를 실행해줘.` |
| 재평가·기업 브리프 | `prompts/03-brief-reevaluation.md를 실행해줘.` |
| 지원 서버 | `prompts/04-application-server.md를 실행해줘.` |
| 자체 폼·Chrome | `prompts/05-browser-extension.md를 실행해줘.` |
| 데모 정리 | `prompts/06-demo-release.md를 실행해줘.` |
| 새 세션에서 재개 | `prompts/resume.md를 읽고 다음 작업 한 개를 완료해줘.` |
| 독립 검토 | `prompts/review.md 기준으로 최근 변경을 검토해줘.` |

각 단계는 요구사항·코드·검증을 묶는다. 한 요청에서 다음 단계 전체까지 자동 확장하지 않고, 현재 단계의 완료 기준을 충족하는 데 집중한다. 로컬에서 해결 가능한 문제는 이어서 수정한다.

## 4. 사용량과 문맥 관리

루트 CLAUDE.md는 짧은 공통 규칙만 담고, 상세 계약은 현재 작업에 필요한 파일만 읽도록 구성했다. `@` import로 모든 문서를 자동 로드하면 문서가 나뉘어도 전체 문맥 비용이 줄어들지 않으므로 이 킷은 그런 구조를 사용하지 않는다.[1]

작업 범위는 `docs/CODEMAP.md`에서 찾고 `rg`로 관련 경로를 좁힌다. 검색 결과 전체·거대한 로그·모든 계약 문서를 매번 대화에 붙여넣을 필요가 없다. 모델은 현재 계정의 선택을 유지하며, 병렬 에이전트를 기본 필수 구성으로 만들지 않는다. 별도 에이전트도 사용량을 소비한다.[2]

긴 작업은 먼저 HANDOFF에 실제 변경과 검증 결과를 남긴다. 같은 폴더의 최근 대화는 다음 명령으로 이어갈 수 있다.[3]

```bash
claude -c
```

대화 이력이 필요하지 않으면 새 세션에서 `prompts/resume.md`를 사용한다. 긴 대화를 정리할 때는 `/compact 승인·접수 계약, 변경 파일, 검증 결과, 다음 작업을 유지해줘`처럼 보존할 내용을 지정할 수 있다. `/compact`도 요약 요청을 발생시키므로 반복 실행을 사용량 절약책으로 가정하지 않는다.[2]

## 5. 기록의 의미

- `docs/state/PROGRESS.md`: 구현·검증 상태의 현재 표. 과거 테스트 결과를 새로운 기능의 PASS로 재사용하지 않는다.
- `docs/state/HANDOFF.md`: 다음 개발자가 시작할 한 작업, 관련 경로, 재현 명령과 막힌 이유.
- `DECISIONS.md`: 바뀐 판단과 이유. 대화 중 임시 추측을 확정 결정으로 남기지 않는다.
- `docs/CODEMAP.md`: 코드 위치 안내. 함수 목록 전체 대신 기능 진입점·테스트·연관 계약을 연결한다.

Claude 지침은 모델에 전달하는 문맥이다. 승인 결속·권한·중복 방지는 실제 코드와 DB 제약, 테스트로 검증한다.[1][2]
