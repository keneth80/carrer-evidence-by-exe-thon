# 6단계 — 통합 검증과 데모 인계

현재 구현을 대회 데모에서 재현할 수 있게 정리해줘. 배포·외부 제출·팀원에게 메시지 보내기는 이번 프롬프트에 포함되지 않아.

## 먼저 읽기

CLAUDE.md, docs/state/PROGRESS.md·HANDOFF.md, README, DECISIONS.md, 관련 검증 기록을 읽어줘. 실제 기능과 계획을 구분해줘.

## 작업

1. 새 개발 환경에서 README만으로 설치·환경 준비·DB·앱·worker 실행이 가능한지 확인하고 막힌 명령을 수정해줘.
2. 합성 자료 기준으로 조건 적용→검색→1~3개 분석→비교·근거 확인→조건 재평가→회사 1곳 브리프를 검증해줘.
3. 브라우저 지원이 구현·검증되었다면 초안→첨부→최종 확인→자체 폼 접수·기록까지 포함해줘. 준비되지 않았다면 그 상태를 데모 범위에 반영해줘.
4. live Liner 사용이 검증된 부분과 mock 부분을 화면·자료에서 구분해줘. 실제 호출 근거·확인 시각·비용 상태를 기록하고 키·개인 정보는 제거해줘.
5. 핵심 실패 사례를 확인해줘: 빈 검색, 부분 분석 실패, 미확인 조건, 늦은 작업 응답, stale 승인, 중복 제출, 접수 응답 손실.
6. 기존 프로젝트에서 가져온 부분과 이번 개발 부분을 구분한 변경 요약, 5분 이내 데모 시나리오, 남은 한계, 최종 제출 확인 목록을 docs 아래에 작성해줘. 대회 제출 형식은 최신 공식 안내를 다시 확인해줘.

## 보고

실행한 명령과 결과, 전체 흐름의 관찰 증거, NOT_RUN·BLOCKED 항목, 공개 전 남은 작업을 구분해줘. 통과하지 않은 검증을 완료로 바꾸지 말아줘. 별도 배포 요청 전까지 로컬 결과를 보존하고 docs/state를 갱신해줘.
