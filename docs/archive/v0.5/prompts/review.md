# 최근 변경 검토

최근 구현을 v0.4 계약과 현재 DECISIONS.md에 비추어 검토해줘. 처음에는 코드를 바꾸지 말고 실제 결함과 검증 공백을 확인해줘. 이 프롬프트만으로 배포·제출을 실행하지 말아줘.

## 검토 범위

- 최근 diff의 실제 경로부터 시작하고 관련 읽기·쓰기·응답·테스트를 따라가줘.
- source·사실·판단 분리, context/revision 결속, 늦은 응답 처리, 후보·회사 제한을 확인해줘.
- worker lease CAS, SSE 중간 오류, 전송 불명 비용·재시도, mock/live 구분을 확인해줘.
- 세션 소유권·Origin·CSRF, 실제 PDF bytes hash, approval·attempt·receipt 관계, idempotency 대상 경로를 확인해줘.
- 확장이 바뀌었다면 sender·frame·document·고정 bridge·실제 File 첨부·재시작 복구를 확인해줘.

해당 변경과 무관한 항목은 생략해줘. 각 발견에는 **영향, 재현 조건, 코드 위치, 최소 수정 방향**을 제시해줘. 추정 문제는 확인된 결함과 분리하고, 없으면 발견 없음과 남은 검증 한계를 보고해줘. 테스트는 구체적 의문을 확인할 범위만 실행하고 결과를 기록해줘.
