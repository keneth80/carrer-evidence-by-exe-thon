# 브라우저 지원 실행 계약 v0.7

상태: 2026-11-18 S05에서 **Chrome × 자체 테스트 폼(self-form.v1)** 조합을 구현·검증했다(임시 프로필 Chrome 자동 검증, `scripts/chrome-apply-e2e.mjs`). Ego 실행 채널과 외부 채용사이트 adapter는 아직 없고 검증하지 않았다(NOT_RUN). 내부 실행 프로토콜은 [EXECUTOR_PROTOCOL](EXECUTOR_PROTOCOL.md).

## 1. 첫 실행 경로

기존 Chrome 확장 골격을 사용해 자체 테스트 폼 한 경로에서 등록한 이력서 첨부→입력 확인→실행 권한 확인→접수 근거 저장을 완성한다. 이후 Ego를 같은 실행 계약에 연결한다. 최초 실제 채용사이트는 지원 URL·폼·계정·접수 확인 방법을 조사한 뒤 site adapter로 추가한다. 자체 폼 검증은 외부 사이트 검증을 대체하지 않는다.

제품 지원 범위는 `실행 채널 × 사이트 adapter × 검증된 기능` 조합으로 관리한다. Chrome 성공이 Ego 성공을 뜻하지 않으며 파일 입력 성공이 제출 완료를 뜻하지 않는다.

## 2. 공통 adapter 동작

아래 이름은 제품 내부의 설계 인터페이스이며 Ego나 Chrome 공식 API 이름이 아니다. 구체적인 JSON 필드는 [v0.7 계약](../contracts/v0.7/README.md)을 따른다.

| 동작 | 검증과 결과 |
| --- | --- |
| `connect` | 실행기·사이트·로그인 계정·정확한 탭/문서를 연결하고 capability 반환 |
| `inspect` | 회사·공고·필수 문항·첨부 조건·지원 마감을 관측하여 schema snapshot 생성 |
| `prepare` | 확정 답변·파일을 입력하고 실제 값과 첨부 identity를 다시 읽음 |
| `verify` | 사용자/정책 권한과 현재 회사·공고·계정·문서·파일 hash·문항을 대조 |
| `submit` | 중복 방지 점유·한도·정책 유효성 확인 후 허용된 한 건을 전송 |
| `observe` | 완료 화면·접수 ID·내 지원 목록 등 지원 대상에 맞는 증거 관측 |
| `resumeObservation` | 재연결 후 이미 전송한 건의 결과 조회. 자동 재제출을 포함하지 않음 |
| `pause` | 새 작업 수신·전송 중단. 진행 중 전송은 결과 관측으로 전환 |

연결 결과에는 파일 첨부·새 탭·iframe·인증 복구 등 지원 가능한 동작을 포함한다. 지원하지 않는 문항·약관·파일 형식·추가 인증은 사용자 확인 필요 상태로 반환한다. 모든 capability를 항상 true로 선언하지 않는다.

## 3. Chrome 확장

현재 `apps/extension/`은 1회 코드로 연결한 기기 토큰으로 서버가 허용한 지원 건만 실행하는 MV3 실행기다(host 권한 `http://127.0.0.1:4310/*` 하나). 쿠키·키·임의 JavaScript를 메시지로 주고받지 않는다. 아래 초기 구현 1~6을 S05에서 자체 폼에 적용했다(DECISIONS S5-01~S5-12).

Chrome의 `activeTab`은 사용자가 확장을 실행했을 때 현재 탭에 주는 일시 권한이다. 다른 origin 이동이나 탭 종료 시 계속 사용할 수 없다.[1] `scripting`에는 대상 페이지의 host 접근 권한도 필요하며, host permission 또는 activeTab이 그 경로다.[2] 따라서 여러 사이트에서 지속 실행하는 자동 지원에는 해당 대상 사이트의 권한과 제품 계정·기기 연결을 설계해야 한다. 설치 권한만으로 사용자 제출 의사가 충족됐다고 해석하지 않는다.

초기 구현:

1. 앱 계정과 확장 연결을 짧은 유효기간의 1회 코드로 맺는 방식 등 명시적인 기기 연결 절차를 설계한다. local/dev 인증과 운영 인증을 구분한다.
2. 앱 API origin과 site adapter 허용 origin을 고정하고 sender·tab·document ID를 검증한다. URL·selector·script를 외부 메시지가 임의로 지정하지 못하게 한다.
3. 폼의 원래 입력값을 확인한 뒤 허용 필드만 채운다. 사이트 script·다른 사용자 입력으로 값이 바뀌면 다시 검토한다.
4. 파일은 서버에서 허용된 artifact만 가져오며 전송받은 실제 bytes와 hash를 대조한다. 확장에 Liner/편집 모델의 비밀키를 보내지 않는다.
5. 최종 제출 직전에 정확한 연결 대상·문서·권한을 재확인한다. service worker의 메모리만으로 승인·접수 상태를 보존하지 않는다.
6. Chrome 재시작·패널 종료 후에는 서버 상태로 복구한다. 다시 연결했다는 이유로 지원 버튼을 반복 누르지 않는다.

사이트가 브라우저의 파일 입력을 받는 방식은 adapter별로 검증한다. 임의 웹페이지에서 사용자의 로컬 파일 경로를 읽을 수 있다고 가정하지 않는다. 확인된 bytes를 첨부하고 사이트가 인식한 파일명·크기·업로드 상태를 관측한다.

## 4. Ego

공식 문서는 설치된 PC에서 `ego-browser`를 실행하는 custom harness 연결을 설명한다. 원격 서버·컨테이너는 사용자 PC에서 명령을 실행하는 공식 host bridge가 필요하다.[3] 따라서 SaaS 서버에 도구를 설치하는 것만으로 사용자의 Ego를 제어하지 못한다.

실제 개발 단계에서는 사용자의 설치 환경에서 `ego-browser skill`이 출력하는 가이드를 먼저 확인한다. 공식 문서도 설치된 실행 파일과 사용 가이드에 맞춰 API를 선택하도록 한다. 웹의 구버전 예제, Playwright API, 현재 TaskSpace/Page API를 섞어 사용하지 않는다.[4]

제품용 로컬 실행기는 다음만 책임진다.

- 인증된 앱 서버에서 자기 계정의 유효 작업을 받아 실행한다.
- 허용된 site adapter·artifact·동작만 실행한다. 모델이 생성한 임의 shell을 실행하는 서비스로 만들지 않는다.
- 브라우저 Space/페이지와 제출 attempt를 연결하여 재개할 수 있게 한다.
- 세션·로그인·파일 첨부·실제 폼 상태를 관측하고 결과를 서버로 반환한다.
- 기기 오프라인일 때 `기기 연결 대기`로 표시한다. 항상 실행되는 클라우드 작업으로 광고하지 않는다.

Ego 문서에는 파일 입력과 파일 선택기를 통한 첨부가 설명되어 있다. 클릭 성공은 저장 성공 증거가 아니므로 결과 화면이나 레코드를 확인해야 한다.[4] 이 프로젝트도 같은 원칙으로 접수 증거를 기록한다.

## 5. 수동 지원과 정책 실행

수동 지원은 사용자가 최종 문서·답변·회사·직무·계정을 확인한 권한을 만든다. 자동 지원은 활성 정책에서 공고별 권한을 발급한다. 둘은 권한 생성 근거가 다르며, 실행 전 검증하는 대상·파일·답변은 모두 고정한다.

정책에서 허용한 범위는 매건 수동 확인 없이 실행할 수 있다. 새 질문·사실·자격 확인·문서 변경이 허용 범위를 벗어나면 사용자에게 넘긴다. 개인정보 동의나 사실 확인 문항은 정책의 허용 범위와 실제 답변 근거가 충족된 경우에만 처리한다. CAPTCHA·추가 로그인은 사용자 작업으로 넘기고 우회하지 않는다.

정책 중지·만료와 전송 경쟁은 서버에서 직전에 검증한다. 전송 권한을 오래전에 발급했다는 이유로 중지된 캠페인의 새 지원을 시작하지 않는다. 이미 전송된 건은 상태 확인을 계속한다.

## 6. 접수 증거와 불확실성

| 관측 | 제품 처리 |
| --- | --- |
| 입력·첨부 완료 | 제출 준비 상태. 접수 완료 아님 |
| 제출 버튼 클릭 결과만 반환 | 전송 시작/접수 확인 중 |
| 해당 회사·공고의 성공 화면/접수 ID 확인 | 근거를 연결하고 접수 확인 상태 |
| 오류 페이지지만 전송 여부 불명 | 확인 필요. 자동 재제출 금지 |
| 전송 전 명확한 필수 입력 오류 | 사용자 수정 대기. 접수된 것으로 기록하지 않음 |
| 네트워크 종료·실행기 재시작 | 서버의 영속 attempt에서 복구하고 결과부터 조회 |
| 채용 결과 통지 | 별도의 채용 단계 이벤트. 접수 상태와 분리 |

자체 테스트 폼은 우리 서버가 접수 저장소를 통제하므로 receipt·중복 키를 직접 검증할 수 있다. 외부 ATS에서는 같은 DB 트랜잭션이나 취소 보장이 존재한다고 가정하지 않는다. 외부 정확히 한 번 제출을 보장한다고 표현하지 않고, 불확실한 상태를 영속 저장해 자동 중복을 줄인다.

여러 사이트에서 같은 공고를 찾았을 때 employer·ATS 공고 ID·원본 URL·지원 계정으로 정규화한다. 회사·제목 유사성만으로 같은 공고라고 확정하지 않는다. 미확인 중복은 검토 대기로 보낸다. 다른 채널을 선택해도 원래 점유가 유지된다.

## 7. 구현 완료 판단

자체 폼 1건을 끝까지 검증한 뒤 정확한 지원 범위를 기록한다. 한글 입력, 파일 bytes, 문항 변경, 계정 변경, 오래된 권한, 탭 교체, 중간 종료, 응답 유실, 재시작, 같은 공고 중복을 확인한다. 실행하지 않은 실제 사이트·Ego·Chrome 검증은 NOT_RUN으로 남긴다. 입력값에 개인 정보가 있는 접수 화면을 공개 데모 자료로 사용하지 않는다.
