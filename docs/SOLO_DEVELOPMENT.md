# 개발자 1인 개발 실행 안내 — v0.9

기준일: **2026-11-17 · 한국 시간**. 사용자가 전체 개발을 맡기로 정했다. 패키지와 작업 방식은 v0.9이며 제품·API 계약과 포함된 기초 코드의 기준은 v0.7이다. 이번 자료에는 사용자 컴퓨터에서 이후 수정한 코드나 실행 결과가 반영되어 있지 않다.

## 1. 개발 책임을 한 사람에게 모은다

개발자가 웹·API·DB·검색·대화 편집·PDF·브라우저·자동화의 구현과 통합을 맡는다. Claude Code는 필요한 코드와 검증을 함께 수행하는 개발 도구다. 협업자의 API 완성이나 업무 분장 회의를 기다리지 않고 같은 작업에서 화면과 서버를 연결한다.

협업자는 원할 때 공고·이력서의 사실 검수, 사용성 확인, 데모 자료를 도울 수 있다. 역할은 아직 배정하지 않았으며 개발 시작이나 완료에 필요한 필수 검토자가 아니다. 개발자가 실제 실행 결과와 인수 기준으로 자체 검증하고, 받은 외부 의견은 후속 개선으로 기록한다. 과거 v0.8 Excel의 ‘담당·검토자·근거를 모두 채워야 완료’ 규칙은 현재 1인 개발의 완료 조건으로 사용하지 않는다.

**첫 제품 목표는 그대로 ‘이력서 → 확인한 경력 → 공고 검색’이다.** 이를 작은 구현 단위로 나누되, 입력 화면만 생겼다고 검색까지 완성된 것으로 표시하지 않는다.

## 2. 현재 개발 여부에 따라 시작한다

### 아직 개발 코드를 수정하지 않았다면

통합 ZIP을 새 폴더에 풀고 `README.md`, `package.json`, `CLAUDE.md`가 있는 폴더를 연다. 루트 README의 Node·npm 환경을 맞춘 뒤 다음을 실행한다.

```bash
npm ci
npm run doctor
claude
```

Claude Code에 다음을 입력한다.

```text
CLAUDE.md와 prompts/solo-start.md를 읽고 실행해줘.
전체 개발은 내가 맡아. 현재 코드를 확인한 뒤 S01의 미완료 부분을
화면·API·DB까지 연결하고, 실제 검증과 다음 작업 기록까지 마쳐줘.
```

### 이미 일부 개발했다면

현재 개발 폴더를 계속 사용한다. 새 ZIP의 앱 코드·DB·설정을 통째로 덮어쓰지 않는다. 기존 변경과 실행 결과를 먼저 확인하고, 1인 운영 지침과 필요한 문서만 현재 내용에 맞게 합친다.

```text
현재 사용자 변경과 구현된 기능을 먼저 확인해줘.
개발자가 전체 개발을 맡는 v0.9 운영 지침을 문서에 병합하되
앱 코드·DB·환경 설정·기존 검증 결과는 보존해줘.
S01이 이미 완성됐다면 증거를 확인하고 다음 미완료 단위를 진행해줘.
```

수정 여부를 모른다면 `git status`와 실제 파일을 먼저 확인한다. Git 기록이 없다고 기존 코드나 데이터를 새 것으로 교체하지 않는다.

## 3. 한 번에 완성할 사용자 동작을 정한다

작업 담당은 모두 개발자이다. 아래 순서는 계획이며, 현재 패키지에서 실제 구현을 마쳤다는 뜻이 아니다. 상태와 완료 근거는 `docs/solo/tasks.json`, `docs/solo/TASKBOARD.md`, `docs/state/`에 기록한다.

| 단위 | 이번에 연결할 결과 | 완료를 확인하는 방법 |
| --- | --- | --- |
| **S01** | 소유권·저장 기반 → 실제 이력서 입력 → 추출 확인 → 확정 경력 | PDF와 텍스트 입력이 UI·API·DB를 통과하고, 원문 근거·확인된 경력을 다시 읽는다. 추출 실패와 다른 사용자 접근을 구분한다. |
| **S02** | 확정 경력 → 검색 계획 → 영속 mock 검색 작업 → 공고 표시 | 다른 이력서가 다른 검색 계획을 만들고, 재시작 뒤에도 작업과 결과가 남는다. |
| **S03** | 실제 Liner 검색 연결 | 준비된 키·예산 범위에서 실제 요청과 출처를 확인한다. mock·저장 결과 재생과 구분한다. |
| **S04** | 공고 선택 → AI 대화 → 변경 비교 → 실제 PDF | 수용한 변경이 문서와 파일에 반영되고 없는 경력을 만들지 않는다. 제품 대화 모델의 실제 품질 검증은 mock 검사와 구분한다. |
| **S05** | Chrome 자체 폼 지원 → 접수 근거 → 제출 이력 | 정확한 파일 첨부와 접수를 관찰하고, 당시 제출본을 다시 연다. 불명 결과를 성공이나 재제출로 처리하지 않는다. |
| **S06** | 기준 공고 고정 → 유사 공고 → 지원서 자동 준비 | 조건·중복을 검사한 공고별 초안이 생긴다. 자동 준비만 선택한 상태에서는 제출하지 않는다. |
| **S07** | 정책에 따른 조건부 자동 제출 | 정책 범위의 매건 제출에는 추가 수동 확인을 강제하지 않는다. 공고별 권한·한도·중지·접수 불명을 검증한다. |
| **S08** | 검증 범위 재현 → 데모·기획서·개발 인계 | 실제 동작과 설명이 일치하는 자료를 만든다. 미구현 기능을 구분하며 서비스 출시 완료로 표시하지 않는다. |
| **S09** | 실제 채용사이트·운영 환경 검증 | 운영 인증·파일 보관을 연결하고 최소 한 실제 사이트 adapter의 입력·첨부·접수 관측을 확인한다. 실제 지원은 사용자의 요청·정책 범위에서 실행한다. |

**첫 요청은 S01 하나를 구현하는 범위다.** S01은 제품 단계 1의 앞부분이고, S02까지 연결·검증해야 ‘이력서에서 공고 검색까지’의 로컬 흐름이 완성된다. 실제 Liner 활용은 S03의 별도 근거가 필요하다.

선행 항목은 실제 연결의 완료 기준이다. Liner 키 등 외부 준비가 남았을 때 독립된 화면·문서 모듈은 mock으로 진행할 수 있지만, 실제 연동을 완료로 기록하지 않는다. S05의 자체 폼 성공을 외부 기업 지원 서비스의 출시 증거로 사용하지 않는다. Ego는 공통 실행 계약에 붙이는 대안 채널로 선택할 수 있으며, 첫 구현에서 Chrome과 동시에 완성할 필요는 없다.

기존 상세 지시문은 `prompts/01-resume-search.md`부터 `prompts/06-demo-quality.md`까지 재사용한다. S01/S02/S03은 첫 제품 단계를 나눈 운영 단위이며 계약 이름을 임의로 바꾸는 지시가 아니다.

## 4. Claude Code 세션은 이렇게 운영한다

코드를 수정하는 세션은 하나를 기본으로 둔다. 필요한 웹·API·DB 파일을 그 세션에서 함께 수정하고 한 사용자 흐름을 검증한다. 별도의 읽기 검토는 필요할 때 선택할 수 있다. 여러 쓰기 세션을 운영하려면 별도 작업 폴더와 편집 경계를 먼저 정한다. 세션이나 에이전트를 늘리는 것이 개발 시간·사용량 절약을 보장하지는 않는다.

시작할 때는 CLAUDE·현재 결정·상태·코드맵과 이번 단위에 필요한 계약만 읽는다. 전체 archive와 모든 프롬프트를 매번 다시 읽히지 않는다. 완료 시에는 실제 바뀐 경계와 남은 위험을 검증하고 결과를 남긴다. 관련 없는 전체 검사를 반복하거나 사용자 확인을 형식적으로 다시 요구하는 절차를 추가하지 않는다.

다음 날이나 새 세션에서는 다음 요청으로 이어간다.

```text
prompts/resume.md를 읽고, 현재 코드와 HANDOFF를 대조해줘.
개발자 1인 개발 기준으로 다음 미완료 단위를 구현·검증해줘.
이미 완료한 부분은 재사용하고 같은 작업을 처음부터 다시 만들지 말아줘.
```

종료 기록은 **완성한 사용자 동작 / 변경 파일 / 실행한 검사와 관찰 / 미실행·남은 결함 / 다음 한 작업**으로 남긴다. AI의 성공 보고만 믿지 않고 개발자가 화면·파일·실행 결과를 확인한다. 브라우저를 실행하지 못했다면 그 항목을 NOT_RUN으로 남겨 실제 관찰이 필요한 범위를 드러낸다.

## 5. 일정과 연결할 서비스의 구분

이번 변경으로 전체 기능을 특정 날짜까지 완성한다고 약속하지 않는다. 11/25 마감과 제출 규격은 이전에 받은 안내를 기준으로 한 정보이므로 최신 안내를 다시 확인한다. 실제 가능한 시간을 확인한 뒤 S01~S03의 결과를 먼저 보고 이후 목표일과 데모 범위를 정한다. 자동 지원은 제품 범위에 유지하며, 미완료이면 후속 작업으로 남긴다.

Claude Code 계정은 개발 도구 이용을 위한 것이다. 제품에서 사용자가 대화하는 모델/API, Liner API, 브라우저 실행 연결은 별도로 구현·설정·검증해야 한다. 기본 로컬 개발은 mock으로 진행하고, 텍스트 PDF 추출은 키 없이 실행 가능한 도구를 검토한다. 이것이 실제 검색·편집 모델의 비용이 없다는 의미는 아니다.
